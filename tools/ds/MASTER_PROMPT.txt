=== ENGINEERING STANDARDS ===
- Kotlin official style. Match the surrounding file's naming, density and comment style. Comments only for intent the code does not state.
- Coroutines: structured concurrency, no GlobalScope, injectable dispatchers, rethrow CancellationException, never block the main thread.
- Compose: unidirectional data flow, hoisted state, no business logic in composables, immutable UI state, content descriptions, 48dp touch targets, Material 3, dark and light themes. Follow the string-resource convention already used in the uploaded files.
- Persistence/state machine: persist every transition before acting on it; stages are idempotent; Room schema changes need a migration and a migration test.

=== DOMAIN RULES (research-backed) ===
- YouTube extraction is volatile (JS runtime, SABR, PO tokens). Let yt-dlp choose clients. Never hard-code client lists or format ids. Surface withheld or missing formats honestly.
- Success means evidence, not exit code 0: verify the output file, the selected format ids, dimensions and extension, and verify publication.
- Retry layers (yt-dlp request retries, whole-task retry with one re-resolve after an expired-URL 403, user retry) are separate and counted separately. Use capped exponential backoff with jitter. Never loop on bot gates or HTTP 429. "Retry from start" is not "Resume".
- Foreground service type dataSync has a time limit on API 35+: handle onTimeout by persisting state and stopping promptly. Android 16 applies job quotas to jobs started from a foreground service.
- Storage: stage in app-private storage, publish via MediaStore with IS_PENDING, sweep orphaned pending rows at startup, and check free space for staging plus merge output plus the published copy. API 24-28 behaves differently.
- Clipboard is read only while the app is in the foreground and only on user action.
